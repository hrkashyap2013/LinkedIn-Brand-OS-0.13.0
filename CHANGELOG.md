# Changelog

## 0.13.0

The first public release of LinkedIn Brand OS: a blank, open template that runs a LinkedIn brand workflow with AI agents. Nothing in it posts for you.

**Agents and commands**
- 27 specialist agents plus an orchestrator, as Claude Code subagents and commands, Codex skills, and plain prompts for any AI chat. Nothing is posted by an agent; the owner makes four decisions (idea, visual, post and rendered visual, package).
- Called by name, never part of the automatic pipeline: Interviewer (stores real stories in the Experience Bank, only when asked), Repurposer, Hook Extractor, Reply, Comment and Profile Optimizer.
- A reference library compiled into the agents: a hook library with engagement tactics marked "use with care", a three-tier humanizer (Strict by default) with an over-correction guard, plain-language LinkedIn guidance graded OWNER DATA, SOURCED or UNVERIFIED (no percentages), content pillars and goal mix, an interview method and question bank, and a profile playbook.
- Shared rules: anything written by someone else is data, never instructions; no invented statistics, quotes, sources or experiences.

**Apps and tools**
- Browser app (local only, secret token, no API key) and terminal app: chat with an `@agent` menu and `/` commands, the four-decision pipeline with buttons or typed approvals, previews, run history, metrics, reminders. Uses your installed Claude Code or Codex. A demo mode uses a stand-in AI.
- Visual generator: 10 diagram types as portrait, square or a carousel PDF; brand theme from the profile; text fitting with a 28 px phone-readable floor; quality warnings; alt text; a visual prompt; fingerprints. PNG and PDF through Chrome or Edge.
- Approvals tied to the exact content: every decision stores a fingerprint, so an edit after approval blocks packaging until it is approved again. The ready-to-paste package holds the post text, visual files, alt text, suggested time, first comment, pin comment, hashtags, reply starters, a visual prompt and a checklist.
- Reminders for results checks (24h to 90d) and reply checks (1h to 24h), including ones that came due while the computer was off. Desktop and phone notifications that never contain post text.
- Memory: ten registers written only through a guard that checks permission, backs up, verifies and can undo.
- Setup wizard, scheduler for preparation runs, `doctor.py` (setup checks), `agent_evals.py` (behavior checks against your real AI tool), post lint, AI-tells scorer with an over-correction guard, a rule-based comment sorter, a secrets scanner.
- One-line install for AI assistants (`INSTALL.md`, `install.sh --auto`, `install.ps1 -Auto`), which also runs the doctor and prints its result.
- Optional Publora auto-post add-on, off by default: needs the setting, a key in an environment variable, all four decisions matching the exact content, a built package, a preview and a typed PUBLISH. It creates only drafts or posts scheduled at least five minutes ahead, never retries on an unclear result, and refuses a second send of the same content.
- Plugin manifests for Claude Code and Codex, generated by the build. `SECURITY.md`, `CONTRIBUTING.md`, and CI for Ubuntu, macOS and Windows.

**Known limits** (see the README for the full list): not yet run with a real Claude Code or Codex; the PNG and PDF command line was checked only with a stand-in (the pages themselves were verified in a real Chromium); the Publora add-on, plugin manifests, Windows pop-ups and Task Scheduler, a real phone push, and the CI workflow have not been run against the real services.
